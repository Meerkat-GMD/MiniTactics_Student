02 · 문제에서 출발하기

Unit이 모든 반응을 알아야 할까?

피해를 받을 때 HP 바, 승패, 효과음, 전투 로그를 Unit에서 직접 호출한다면 새 반응을 추가할 때마다 Unit을 고치게 됩니다.

변하지 않는 사실

어느 유닛의 HP가 바뀌었다.
어느 유닛이 사망했다.

달라질 수 있는 반응

바를 줄인다. 결과를 계산한다.
소리를 낸다. 로그를 남긴다.

생각해 보기: 소리를 끈 게임에서도 HP 계산은 그대로 작동해야 합니다. 두 책임을 어디서 나눌까요?

03 · Observer의 역할

사실을 알리고, 필요한 곳에서 듣는다

발행자 Unit→HpChanged / Died→구독자 HP 바 · GameManager

발행자는 사건을 만들고 구독자는 콜백을 등록합니다. Unit은 구독자의 구체 타입이나 화면 표현을 몰라도 됩니다.

효과

새 구독자를 추가해도 Unit의 HP 계산과 UI가 얽히지 않습니다.

책임

구독 수명과 알림 순서를 관리해야 합니다. 참조 연결 자체가 사라지는 것은 아닙니다.

04 · 패턴은 서로 다른 문제를 맡는다

Singleton · State · Command · Observer

패턴이번 장면에서 맡는 일
SingletonGameManager의 유일한 전투 결과와 수명
State선택·이동·공격 단계별 클릭 의미
Command이동 실행과 위치·HasMoved 복구
ObserverHP·이동·사망 사실을 여러 반응에 전달

Unit이 GameManager.Instance를 불러 전멸을 판단하지 않습니다. GameManager가 Unit.Died를 관찰합니다.

05 · 알림의 이름과 데이터

C# event는 발행 권한을 지킨다

public event Action<Unit> HpChanged;
public event Action<Unit, Vector2Int, Vector2Int> Moved;
public event Action<Unit> Died;

외부는 +=로 듣고 -=로 듣기를 멈춥니다. Invoke는 이벤트를 선언한 Unit 내부에서만 합니다.

HpChanged는 변경된 Unit을 전달합니다. 구독자는 이미 갱신된 CurrentHp를 읽습니다. Moved는 출발 셀과 도착 셀까지 전달합니다.

왜 Died의 인수에 사망한 Unit이 필요할까요?

06 · 반응에는 시작과 끝이 있다

+=와 -=는 한 쌍이다

_unit.HpChanged += HandleHpChanged;
_unit.HpChanged -= HandleHpChanged;

이름 있는 콜백

등록할 때와 해제할 때 같은 메서드를 사용합니다. 서로 새로 만든 람다는 같은 구독을 가리키지 않을 수 있습니다.

중복 구독

OnEnable과 Bind가 모두 불릴 수 있습니다. 구독 플래그로 중복을 막고 실제 대상이 바뀌기 전에 해제합니다.

이번 이벤트는 동기 호출입니다. 발행 중 구독자들이 호출되며, 긴 처리나 예외는 발행 흐름에도 영향을 줍니다.

07 · 알림은 이미 일어난 사실이다

HP를 먼저 저장하고 알린다

유효 피해 확인→CurrentHp 저장→HpChanged

피해가 0 이하이거나 이미 사망한 유닛이면 아무 변화도 없습니다. HP는 0 아래로 내려가지 않습니다.

_currentHp = Mathf.Max(0, previousHp - damage);
HpChanged?.Invoke(this);

순서를 뒤집으면 HP 바가 읽는 값은 이전 HP일까요, 새 HP일까요?

08 · 사망은 한 번의 상태 전이

HP 0과 비활성화 사이의 순간

HP → 0→HpChanged→Died→SetActive(false)

이전 HP > 0 && 현재 HP == 0인 경우에만 사망 사건을 발행합니다. 사망 후 다시 피해를 받아도 Died가 반복되지 않습니다.

Died를 받는 동안 유닛 오브젝트는 아직 활성일 수 있습니다. 생존 판단에는 IsAlive가 필요합니다.

HP 바와 승패 구독자의 등록 순서에 의존하지 않습니다. 두 구독자는 이미 저장된 HP라는 같은 사실을 읽습니다.

09 · 기존 이동도 사실을 알린다

Moved: 어디에서 어디로 갔는가

Vector2Int sourceCell = board.WorldToCell(transform.position);
transform.position = board.CellToWorld(targetCell);
// 다른 셀로 이동했을 때만 출발·도착을 알린다.
Moved?.Invoke(this, sourceCell, targetCell);

실제 구현에서는 null 보드와 같은 셀을 걸러 냅니다. 위치가 먼저 바뀌므로 콜백에서 읽는 위치와 도착 셀이 일치합니다.

MoveUnitCommand와 Undo도 MoveTo를 이용합니다. Moved를 구독한 연출은 이동 방향과 되돌아가는 이동을 함께 관찰할 수 있습니다.

10 · 전투 규칙을 계산으로 분리

방어자가 서 있는 지형을 읽는다

피해 = max(1, 공격력 − 방어력 − 지형 방어)

방어 지형방어 보너스공격 6 · 방어 1
평지05 피해
숲14 피해
산23 피해

이동 비용은 평지 1·숲 2·산 3입니다. 이동 비용과 방어 보너스를 혼동하지 마세요. 강은 이동 불가이며 방어 보너스는 0입니다.

11 · 모델의 값을 화면의 비율로

HP 바는 HP를 소유하지 않는다

Unit

MaxHp 10, CurrentHp 5.
게임의 실제 상태를 저장합니다.

UnitHealthBar

5 / 10 = 0.5.
Fill Transform의 localScale.x를 바꿉니다.

scale.x = Mathf.Clamp01(_unit.CurrentHp / (float)_unit.MaxHp);
_fill.localScale = scale;

float 변환이 없으면 정수 나눗셈으로 5/10이 0이 됩니다. x만 변경하여 바의 높이와 깊이를 유지합니다.

12 · 켜질 때 듣고, 꺼질 때 정리한다

OnEnable · OnDisable · Bind

진입점해야 하는 일
OnEnableSubscribe → Refresh
OnDisableUnsubscribe
Bind(newUnit)옛 대상 해제 → 새 대상 저장 → 구독 → Refresh
HandleDied바 오브젝트 비활성화

잠시 꺼져 있던 동안 놓친 변화는 OnEnable의 Refresh로 회복합니다. 콜백에서는 구독 상태와 전달된 Unit이 실제 바인딩 대상인지 확인합니다.

Bind에서 _unit을 먼저 바꾸면 누구에게서 구독을 해제하게 될까요?

13 · 같은 사건, 다른 관심사

GameManager는 Died를 듣는다

Unit.Died→HandleObservedUnitDied→생존 팀원 수→TryFinish

적 팀 생존 전투 유닛이 0이면 PlayerWon, 아군 팀이 0이면 PlayerLost입니다. 현재 결과가 Playing일 때만 새 결과를 확정합니다.

집계 조건은 활성 상태, IsAlive, IsTurnUnit, 같은 Team입니다. Fixed Blocker는 제외합니다.

관찰은 Start에서 직렬화 목록 5명으로 시작합니다. 대상 교체와 OnDestroy에서 해제합니다. HP 바의 OnDisable 수명과는 다릅니다.

14 · 승리 조건이 추가되어도 결과는 하나

전멸과 목표 점령이 공존한다

사건결과
마지막 적 사망PlayerWon
마지막 아군 사망PlayerLost
아군이 적 소유 목표 (11,6) 진입PlayerWon
적이 아군 소유 목표 (0,4) 진입PlayerLost

GameManager.TryFinish는 최초 결과를 보존합니다. TurnManager가 Finished로 전환하면 HUD가 결과를 보여 주고 플레이어 입력이 막힙니다.

R은 결과 이후에도 새 장면을 불러옵니다. HP·유닛 활성 상태·턴·구독이 새 장면 수명으로 시작합니다.

15 · 유효한 대상부터 정한다

상하좌우 한 칸의 살아 있는 적

|dx| + |dy| == 1

대상이 되는 경우

다른 팀, 활성 상태, HP 양수,
현재 보드에서 직교 인접.

대상이 아닌 경우

자기 자신·동료·대각선·사망·비활성.
전투 목록에 없는 고정 장애물.

AttackTargeting은 후보를 모으는 제공 도우미입니다. BattleController와 EnemyAI는 자기 행동의 소유권·전투 참여 조건도 확인합니다.

16 · 이동 다음 클릭의 의미가 바뀐다

AttackState로 공격 선택을 유지한다

Idle→UnitSelected→이동·목표 확인→AttackState→Idle

이동 뒤 인접 적이 있으면 공격 대상을 보여 줍니다. 없으면 바로 행동을 완료합니다. 목표로 게임이 종료되었다면 공격 선택을 열지 않습니다.

PlayerMoveCommand가 이동 시 HasMoved를 true로 만듭니다. 공격을 기다리는 보류 행동은 그와 별도로 관리합니다.

학생판의 이동 전용 경로는 바로 완료됩니다. 전투를 완성하면서 ExecuteMove의 후속 흐름을 AttackState에 연결합니다.

17 · 공격과 건너뛰기의 경계

유효한 공격 또는 빈 공간 클릭

AttackState의 입력처리
유효한 인접 적TryAttack 성공 → CompletePlayerAction
빈 공간공격을 건너뛰고 CompletePlayerAction
동료·유효하지 않은 대상공격 선택 상태 유지
피해 전 Undo보류한 이동만 복구 → 표시·보류 정리 → Idle
Enter (기본·숫자패드)공격 건너뛰기·행동 완료 → 아군 턴 종료
다른 아군 선택보류 행동 중에는 실행하지 않음

완료는 보류 중인 실제 유닛에게 한 번만 적용합니다. 마지막 아군 행동이면 적 턴으로 넘어가므로 중복 완료를 막아야 합니다.

18 · 되돌릴 수 있는 범위를 분명하게

피해를 준 뒤에는 이동 이력을 비운다

이동 Command의 Undo는 위치와 HasMoved만 복구합니다. 적의 HP·사망·승패까지 복구하는 전투 Undo는 이번 범위가 아닙니다.

공격이 적용됨

실제 HP 감소를 확인하고 history.Clear. 위치만 되돌리는 모순을 막습니다.

아직 피해가 없음

공격 대기 중 Undo는 그 이동의 셀·HasMoved=false를 복구합니다. 다른 유닛 이력은 보존합니다. 적 턴 진입 시 이력은 비워집니다.

피해 알림 중 추가 입력이 재진입하지 않도록 처리 중 상태를 둡니다. 피해 적용과 이력 정리가 끝난 뒤 행동 완료를 처리합니다.

19 · 적도 동일한 피해 규칙을 사용

인접 적이 있으면 제자리에서 공격

ChooseAttackTarget은 살아 있는 아군 전투 유닛 중 인접 대상을 고릅니다. 여러 명이면 다음 순서로 비교합니다.

현재 HP 낮은 순→y 작은 순→x 작은 순

공격 대상이 이미 있으면 이동하지 않습니다. 공격은 방어자의 셀에서 지형을 읽고 CombatCalculator와 TakeDamage를 사용합니다.

두 아군의 HP가 같아도 실행할 때마다 결과가 달라지지 않으려면 무엇이 필요할까요?

20 · 이동한 뒤 상황을 다시 읽는다

멀리 있으면 접근 → 재검색 → 한 번 공격

  1. 가까운 아군을 거리 → y → x로 선택합니다.
  2. ChooseDestination의 거리 → 이동 비용 → y → x 규칙으로 이동합니다.
  3. 취소·게임 종료·생존 상태를 다시 확인합니다.
  4. 현재 위치에서 인접 대상을 다시 찾고 최대 한 번 공격합니다.

더 가까워지는 칸이 없으면 제자리에 머뭅니다. 이 AI는 결정 가능한 탐욕 규칙이며 복잡한 장애물을 돌아가는 장기 계획은 하지 않습니다.

21 · 적 한 명의 행동이 끝난 뒤 다음 적으로

UniTask는 순서와 수명을 연결한다

await enemyAi.TakeCombatTurnAsync(unit, _units, cancellationToken);
// 전멸 결과와 목표 도착을 확인한 뒤 다음 유닛으로 진행한다.

사망한 적은 차례에서 제외됩니다. 게임이 종료되면 다음 적을 실행하지 않습니다. 이동 직후·대기 중에도 취소와 종료를 확인합니다.

위치 변경은 즉시 일어나며 350ms는 행동 사이의 대기입니다. R로 장면을 바꾸면 이전 턴 작업의 수명을 끝냅니다.

학생 시작 경로는 완성된 TakeTurnAsync로 적을 목표 쪽에 이동시킵니다. 전투 구현 후 호출을 바꿉니다.

22 · 코드를 움직이는 직렬화 참조

다섯 전투 유닛, 다섯 HP 바

23 · 사실이 끊어진 지점을 찾기

값 → 알림 → 구독 → 반응 순서로 좁힌다

증상먼저 확인할 연결

24 · 150–170분의 전술 실험

예측한 피해와 실제 게임을 비교한다

  1. Player 3 (8,6) → (9,7) → Enemy 1 (9,8): 평지 피해 5, HP 10→5, 바 절반.
  2. R 후 같은 이동에서 피해 전 Undo, 빈 공간 건너뛰기, Enter 턴 종료를 비교합니다.
  3. 방어자를 숲·산에 배치해 피해 4·3을 비교합니다. 유효하고 비어 있는 셀을 사용합니다.
  4. 적의 제자리 공격과 이동 후 공격, 사망 유닛 제외, 전멸 VICTORY·DEFEAT를 관찰합니다.

기록: 행동 전 HP / 방어 지형 / 예측 피해 / 실제 HP / 바 변화 / 턴 결과. 짝과 조작자·관찰자 역할을 바꿉니다.

25 · 새 기능이 기존 게임을 이어 간다

목표·입력·재시작도 함께 확인

  • 아군이 적 소유 목표 (11,6)에 들어가면 승리합니다.
  • 적이 아군 소유 목표 (0,4)에 들어가면 패배합니다.
  • Enter로 남은 아군 행동을 넘깁니다. 적 턴·종료·피해 처리 중에는 Enter와 Undo가 차단됩니다.
  • R로 HP 10/10, 유닛 활성 상태, 플레이어 턴이 새로 시작됩니다.
