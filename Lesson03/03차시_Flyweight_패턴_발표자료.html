Two Kinds of Data

무엇을 공유하고 무엇을 남길까?

Intrinsic · 공유

  • 지형 이름
  • 이동 비용
  • 통행 가능 여부

Extrinsic · 문맥

  • 셀 좌표
  • 현재 점유 유닛
  • 강조 표시 상태

Immutable

공유 객체는 함부로 바뀌면 안 된다

public string Name { get; }
public int MovementCost { get; }
public bool IsWalkable { get; }

숲 객체 하나를 40칸이 공유한다. 한 곳에서 비용을 바꾸면 40칸 모두에 영향을 준다. 그래서 생성 뒤에는 읽기만 허용한다.

Canonical Objects

네 종류는 딱 한 번 생성한다

Plain    = new TerrainType("평지", 1, true);
Forest   = new TerrainType("숲",   2, true);
Mountain = new TerrainType("산",   3, true);
River    = new TerrainType("강",   1, false);

모든 P는 같은 Plain을, 모든 F는 같은 Forest를 참조한다.

Change Pressure

가장 적은 칸 ≠ 가장 싼 길

위 → 오른쪽

숲 2 + 평지 1 = 3

오른쪽 → 위

평지 1 + 평지 1 = 2

둘 다 두 칸이지만 비용은 다르다.

Dijkstra, Reduced

항상 누적 비용이 가장 작은 셀부터

  1. 시작 비용을 0으로 기록한다.
  2. frontier에서 가장 싼 셀을 꺼낸다.
  3. 이웃 지형 비용을 더한다.
  4. 더 싼 경로라면 비용과 이전 셀을 갱신한다.

Relaxation

더 싼 길이면 기록을 바꾼다

candidate = costs[current] + terrain.MovementCost;

if (knownCost <= candidate)
    continue;

costs[next] = candidate;
previous[next] = current;

Blocked

강은 비싼 길이 아니라 없는 길이다

if (!terrain.IsWalkable)
    continue;

비용을 아주 크게 주는 방식은 큰 예산에서 강을 건널 수 있게 만든다. 통행 불가는 별도 규칙이어야 한다.

Use It When

Flyweight 적용 기준

도움이 된다

  • 동일 데이터가 매우 많이 반복된다
  • 공유 데이터가 거의 변하지 않는다
  • 개별 문맥과 분리할 수 있다

과할 수 있다

  • 객체 수가 매우 적다
  • 각 객체의 데이터가 모두 다르다
  • 공유 변경이 독립성을 깨뜨린다

Takeaway

오늘의 핵심

  1. 공유할 규칙과 셀별 문맥을 분리한다.
  2. 지형 종류 객체는 네 개만 만들고 120개 셀이 참조한다.
  3. 누적 비용이 가장 작은 후보부터 탐색한다.
  4. previous를 따라 최저 비용 경로를 복원한다.
  5. 검증 뒤의 이동과 Undo는 기존 Command를 재사용한다.

같은 것은 공유하고, 달라지는 것은 문맥에 남긴다.
